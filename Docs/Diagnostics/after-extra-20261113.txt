Local fix implemented after user authorization (2026-11-13):
- ScreenTimeEnforcer preserves a valid registered cumulative window when only
  total allowance increases. It updates the saved signature without stop/start;
  the existing endpoint retires normally and the next window includes extras.
  Withdrawals, selection/day/restart changes, stopped/finished/legacy monitors
  still rearm. Signature version3 forces one migration from the old version2.
- An early intermediate event remains ignored. An early terminal event now
  retires the exhausted notification generation WITHOUT charging its usage.
  The monitor extension uses its existing fenced coordinator to arm a replacement.
  Queued old events cannot debit or restart that replacement.
- Two automatic replacement attempts are allowed. A third consecutive early
  terminal failure preserves the balance but shields selected apps and stops
  usage monitoring. This avoids unlimited untracked use and IPC retry loops.
  NSE/host do not acknowledge an unlock backed by this failed monitor.
- Retry state survives process restart and same-policy refresh; real accepted
  usage, a newer parent budget policy or a new day reset it. Parent can change
  the allowance to retry after persistent failure. Reinstall recovery never
  restores the previous installation's retry/monitor ownership from the server.
- DailyBudgetStore.arm now compares the full expected state under the existing
  file lock, including retry state. No lock spans DeviceActivity IPC.
- Local diagnostics: monitor.early_terminal / shield.monitor_recovery_exhausted.
  Recovery without new usage does not schedule an extra upload. No backend,
  polling, timers, APNs routing, uploader cadence or subscription policy changes.
